Purpose

Harden and improve the reinmann Lean 4 formalization: bring the working tree back under version control, verify the full build and axiom-cleanliness, consolidate the sprawling documentation into one canonical architecture map, add CI guards, and advance the verified frontier one honest rung (the order-3 Toeplitz/moment positivity target and the Li-criterion draft). This plan does not — and cannot — prove the Riemann Hypothesis. The repo itself encodes this correctly (see RHReductionCapstone.lean: assuming the capstone input is "mathematically identical to axiom rh"). What the plan can do is maximize the size and quality of the machine-verified conditional territory.

Problem

The repo is in strong mathematical shape (0 sorry, 0 axioms across ~50 modules as of the last safe-verify) but poor engineering shape: 8 modified files and ~20 untracked files (new Lean modules, two papers, a zip bundle, LaTeX aux junk, .DS_Store) sit uncommitted on branch rh-structural-theory; ~20 overlapping top-level status/summary markdown files duplicate and partially contradict each other; there is no CI, so nothing prevents a future commit from introducing a sorry or a stray axiom; and the current mathematical frontier (Order3FrontierTheorem in RHTheoremTargets.lean, the Li-criterion draft in research/lean-drafts/) is identified but not yet advanced in Lean.

Solution

Five phases, ordered so each locks in the previous: (1) repo hygiene — gitignore, triage, and commit the untracked work in coherent commits; (2) full-build and axiom audit — lake build plus a scripted #print axioms sweep proving the 0-sorry/0-axiom claim still holds with the new modules; (3) documentation consolidation — one canonical ARCHITECTURE.md replacing the status-file sprawl, with the old files archived; (4) frontier advance — promote LiCriterion.lean.draft into the build and prove the concretely provable pieces of the order-3 positivity rung (rational/interval arithmetic over the explicit xi coefficients, using the existing norm_num-style certificate patterns in VdpCertificates.lean); (5) CI — a GitHub Actions workflow that builds and runs the guard script on every push.

Questionables

Can this plan "prove the Riemann hypothesis" as requested?

No. RH is an open problem; no engineering plan closes it. The repo's own RHReductionCapstone.lean documents why axiomatizing the missing input would be circular. This plan honors the request's achievable core: improve the codebase and push the verified conditional frontier as far as current mathematics allows.

Should the Li-criterion draft be promoted even if it still needs restructuring?

Assumption: yes, provided it can reach the 0-sorry bar by encoding open inputs as named hypotheses (the repo's established idiom). If it cannot, it stays a draft and the task is marked [f] with a note.

Commit or ignore alphaproof-nexus-results/ and the PDFs?

Assumption: commit compiled paper PDFs (they are referenced deliverables already tracked once) but ignore the zip bundle and LaTeX aux files. The nexus-results directory is decided at inspection time in Phase 1; default to commit if any research log cites it.

Is truncated order-3 determinant positivity worth formalizing?

Assumption: yes — it converts the numeric frontier evidence in ORDER3_TOEPLITZ_FRONTIER_LOG.md into machine-checked certificates and isolates the residual analytic gap as a single named hypothesis, sharpening exactly what remains open. Risk: rational-arithmetic proofs can be slow to elaborate; mitigate with precomputed certificates as in VdpCertificates.lean.

Plan images are inline SVG, not generated PNGs

The image-generation sub-workflow requires OPENAI_API_KEY, which is not set in this environment. Self-contained SVG figures matching the :root identity were embedded instead; they can be regenerated as PNGs later via the Update sub-workflow once a key is available.

Notes

  • Honesty pattern: the repo's established idiom is named hypothesis structures (e.g. Order3FrontierTheorem, XiToeplitzTotalPositive) rather than axioms. All Phase 4 work must follow it; #print axioms is the arbiter.
  • The three-level ladder (from RHTheoremTargets.lean): Level 1 = order-3 Toeplitz/PF rung beyond Turán; Level 2 = all contiguous factorial-weighted kernel minors; Level 3 = full PF positivity, the RH-equivalent capstone input. This plan touches only the finite fragment of Level 1.
  • Dependencies: no new libraries. Lean toolchain v4.30.0 via elan; mathlib per lake-manifest.json. CI needs a GitHub remote — verify with git remote -v before Phase 5.
  • Rejected approaches: (a) declaring the capstone as an axiom to "finish" RH — circular, explicitly rejected by the repo's own docs; (b) squash-committing all untracked work in one blob — loses reviewability; (c) deleting the status markdowns — they carry research narrative, so archive instead.
  • Future work: paper submission checklist (paper/SUBMISSION_CHECKLIST.md) is out of scope here but Phase 3's ARCHITECTURE.md should feed it; a de Bruijn–Newman flow module is sketched in research logs and could become a fifth route later.
